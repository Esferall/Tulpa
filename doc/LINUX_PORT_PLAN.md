# Linux 完整移植实施计划

本文件记录 Linux 终端版的初始实现范围与阶段验收。
后续功能和最新回归结果见 [Linux 验收记录](LINUX_ACCEPTANCE.md)。

## 分工

- Codex：平台适配、读取器、SL、媒体、完整业务 API、CLI、安装和发行。
- Claude Code：`chatlocal/tui/` 和 `scripts/check_terminal_tui.py`。
- 前端通过 `TerminalClient` 调用真实后端；不得用模拟成功代替尚未完成的接口。

## 实施阶段

1. 平台基础：POSIX 文件锁、Linux 进程身份/进程组、退出清理和后台工作线程。
2. 本机数据：Linux QQ/微信目录发现、明确账号选择、密钥适配、快照/增量读取和媒体。
3. SL：Linux 官方运行包检查、进程托管、凭据存储、初始化/账号绑定/停止恢复。
4. 媒体：Linux 语音运行时与模型准备、OCR 和 Office 解析依赖及能力状态。
5. 业务：原聊天浏览、回复审批、记忆、关注卡、文件/证据、工作区和模型对话 API；
   TUI 页面与 CLI 命令；模型调用和发送继续由用户的具体操作触发。
6. 发行：可重建安装、用户级 systemd 安装/管理、Linux 源码发行包和桌面终端入口。
7. 集中验收：先检查新增模块，再运行相关已有回归与完整前后端联调；集中修复缺陷。

## 完成判据

- API、CLI、TUI 使用同一份原业务实现和数据库，权限、审核与取消流程不降级。
- 安装脚本支持 x86_64/aarch64，应用报告真实依赖与平台能力。
- 不将工具缺失、QQ/微信未安装、无密钥或无操作系统读取权限伪装为读取成功。
- 真机版本/账号、实际模型和长时间收发未验证时，在最终结果明确列出；不得据模拟测试
  宣称第三方账号登录稳定性或全版本客户端兼容。
- 使用隔离数据和合成协议服务验证接口；真实账号操作与模型调用单独记录。
